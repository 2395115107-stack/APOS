# Manifesto

## APOS 的信念

这是你的开发系统，不是 GitHub 模板。

APOS 相信：

- 产品目标比实现冲动更重要
- 流程编排比角色堆叠更重要
- 文件记忆比对话记忆更可靠
- 经验回写比一次性交付更有价值
- AI 应该成为长期协作系统的一部分，而不是一次性生成器

## 工作哲学

### 1. 先理解，再实现

如果目标不清，最好的实现也可能只是跑偏得很快。

### 2. 先流程，再角色

角色越多，越需要 workflow 统一调度。

### 3. 先落文件，再继续

长任务不能依赖短上下文。重要信息必须持久化。

### 4. 先验证，再完成

没有 review / test 的完成，只是“看起来完成”。

### 5. 先回写，再进化

系统不会因为做过很多事而自动变聪明。只有经验被写回，系统才会成长。

## 判断优先级

```text
产品目标
  > 用户场景
  > 系统规则
  > workflow
  > agent 职责
  > skill 建议
  > 临时实现便利
```

## 最终目标

让 APOS 成为一个会工作的系统，也成为一个会学习的系统。
