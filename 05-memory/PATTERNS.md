# Patterns

## 记录规则

这里记录 APOS 中可复用的工作模式。

好的 pattern 应该说明：

- 适用场景
- 使用方法
- 输入
- 输出
- 注意事项

---

## PAT-001：Owner / Next / Inputs / Outputs / Skills / Writeback

### 适用场景

所有 workflow、agent 输出、任务状态记录。

### 模式

```text
Owner: 当前责任角色
Next: 下一责任角色
Inputs: 输入文件
Outputs: 输出文件
Skills: 使用过的 skill；未使用则写 none
Writeback: 回写文件
```

### 价值

让任务可以被交接、追踪、回写。

---

## PAT-002：Planner 先铺路

### 适用场景

复杂任务、新功能、跨角色协作。

### 模式

planner 不只拆任务，还要先产出：

- 目标澄清
- 任务列表
- 输入输出文件
- owner / next owner
- 是否需要专项 tester

### 价值

减少后续 agent 重复理解上下文。

---

## PAT-003：Tester 只读

### 适用场景

review 后验收、回归测试、专项测试。

### 模式

tester 只输出 PASS / FAIL、问题列表和报告路径，不直接修改代码或文档。

### 价值

保持验证角色独立，避免测试者直接改变被测对象。

---

## PAT-004：重测只验证失败项

### 适用场景

修正循环。

### 模式

如果上一轮测试已经列出失败项，下一轮优先验证这些问题是否修复。只有改动范围很大时才全量重测。

### 价值

减少重复审查，提高长任务效率。

---

## PAT-005：AGENTS.md 是地图，不是百科全书

### 适用场景

总规则、项目入口、agent 上下文设计。

### 模式

`01-core/AGENTS.md` 只放稳定规则、优先级、边界和索引。具体产品、设计、技术、流程、经验分别放到对应目录。

### 价值

减少总规则膨胀，让 agent 先读小入口，再按需展开上下文。

---

## PAT-006：Memory Review / 文档园艺

### 适用场景

完成一批任务后，或发现 agent 重复犯错时。

### 模式

定期检查：

- 哪些 lesson 已过期
- 哪些 lesson 应升级为 pattern
- 哪些 decision 需要复核
- 哪些文档和当前结构不一致
- 哪些信息只是一次性噪音，应该清理

### 价值

控制文档熵增，让 APOS 不只是积累内容，而是持续变清晰。

---

## PAT-007：Run / Eval 分离

### 适用场景

所有任务完成、失败或阻塞后。

### 模式

`RUNS.md` 记录发生了什么。

`EVALS.md` 判断做得怎么样。

### 价值

避免把过程记录和质量判断混在一起，让 APOS 能长期观察 agent、workflow 和 memory 的真实表现。

---

## PAT-008：Loop Specification

### 适用场景

需要多轮推进、验证反馈会改变下一步、并且结果需要写回 memory 的任务。

### 模式

```text
Trigger
  -> Goal
  -> Workflow / Agents
  -> Verification
  -> Terminal State
  -> Memory
```

### 使用方法

每次进入 loop 前先写清：

- 触发来源
- 本轮目标
- 内部 workflow
- 验证方式
- 终态
- 最大轮次 / 时间 / 成本
- 写回文件

### 价值

让 APOS 从“按流程做事”升级为“能判断何时开始、何时继续、何时停止、如何自我改进”的闭环系统。

---

## PAT-009：确定性检查优先

### 适用场景

所有评审、验收、发布检查。

### 模式

进入判断性评审前，先跑 L1 / L2 确定性检查（构建、测试、lint、schema、字段完整性）。检查失败直接生成 findings，不占用判断性评审。

### 价值

机器能查的问题不以评审成本解决，判断性评审聚焦行为、架构、风险。

---

## PAT-010：高风险操作人工确认

### 适用场景

发布、部署、删除、迁移、外发等不可逆或外向操作。

### 模式

agent 说明操作内容、影响范围和回退方式 → 人工明确同意 → 执行 → 确认记录写入当次报告。检查点定义见 `04-development/PERMISSIONS.md`。

### 价值

不可逆操作永远有人类决策记录，agent 不会在边界外自动行动。

---

## PAT-011：报告落盘，路径即证据

### 适用场景

review、test、hotfix、release 的全过程记录。

### 模式

报告统一写入 `10-reports/{RUN-ID}/`，头部写明任务、时间、结论、问题数量；对话与交接块只引用路径。

### 价值

验证证据可追溯，主上下文不被报告内容污染，evaluation 可以按 RUN-ID 回查。
